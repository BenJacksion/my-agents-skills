修改重要专业判断时，在原研究记录补充：结论、来源 URL 或本地资料定位、资料版本、采集/核验日期、核验方式、截断或读取限制，以及它属于原文事实、工程综合还是自行构造示例。网页能打开不代表结论已经核验。

复核由实际变化触发：平台行为或标准版本变化、来源失效、出现反例、消费者受影响，或准备依据该结论进行实际实施。根据来源易变程度确定复核范围，不为所有历史研究机械设置同一过期时间。没有复核时保留原日期和未知状态。

## 版本标识与影响范围

- 仓库版本以 Git commit 为准；有未提交修改时记录差异，不能只写 HEAD。
- 分发内容以 `bundle-manifest.json` 的文件清单和哈希识别；它不覆盖 Git 历史或远端发布状态。
- 已有 Skill 的 `metadata.version` 是该 Skill 的维护者版本，不代替源码 commit；更新执行规则或输出契约时同步说明兼容性。纯格式或链接修正无需给全仓库统一升版。
- 调用名、目录、输入输出语义和依赖分别评估。改名/删除、规则收紧、交接字段含义变化需要记录消费者影响和迁移方式；可选参考和案例的补充也要验证链接与分发。

每次变更检查：专业方法 → Skill → Agent/阶段路由 → 依赖包 → 场景/计算用例 → 消费者。只重跑受影响的专业检查；共享工具变更运行回归。语义或路由修改需要真实行为评估，静态检查不可替代。

## 变更交付记录

在提交说明或研究记录中保留问题、改变的行为、影响范围、验证命令/环境/结果和未运行项。跨域或分发规则变化也在[变更记录](changes.md)留下入口，不要求每个排版修改单独创建文档。

发布或同步前依次核对：

1. 静态校验、维护工具测试与相关专业例子实际执行成功。
2. 新包在干净目录通过引用和内容完整性检查；必要时复现专业例子。
3. 若改变路由或执行判断，完成对应[行为评估](evaluation.md)，记录评审者和结果；未运行时明确保留为发布限制。
4. 下游调用名、引用、版本与未决项一致，使用者可以识别回退条件。

CI 的职责见[工作流](../.github/workflows/validate.yml)：本地执行同样命令成功不表示远端工作流已运行。行为评估、真实业务验证和平台验收各自报告状态。
