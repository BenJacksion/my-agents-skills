# 填写完整的最小交付样例

以下均基于[教学输入](inputs.md)。它们展示字段的必要粒度，不要求每个任务生成三份文件；局部问题可合并为几段说明。事实、假设、决策和验证状态保留原性质。

## 决策样例 D1

**问题**：如何保留主负责人历史，同时允许审核角色参与？

**证据**：E3 要求角色、有效时间与来源；E7 给出换人边界和 Reviewer。两者都是教学输入。H2“语义投影能帮助整合”仍是假设。

**候选**：覆盖工单当前负责人；或保存有独立标识的 Assignment。前者无法单独回答历史与角色问题，除非另有可靠历史来源。

**决策**：在本教学模型中使用 Assignment，区间为 `[validFrom, validTo)`；当前 Primary 由有效记录查询派生。工单模块仍为写权威，不由 RDF 推理产生写授权。

**代价与复审**：需要管理区间重叠和更正；记录时间不等于完整双时间历史。若只需当前值且已有可信审计，可评估更简单投影；若需还原“当时已知什么”，追加记录版本与撤回语义。

**责任**：案例维护者维护示例；真实项目由领域/数据负责人确认业务语义和迁移前提。

## 验证报告样例 V1

| 项目 | 内容 |
| --- | --- |
| 范围 | 本体教学模型的查询、SHACL、OWL 与受控迁移 |
| 可识别输入 | 分发清单的文件 SHA-256，或记录仓库 commit 与工作区差异 |
| 执行入口 | Skill 内 `scripts/verify_example.py`；依赖与配置见本体案例说明 |
| 历史证据 | [研究记录](../../../domains/ontology-modeling/research.md#2026-10-30-工程补充与运行证据)已记载 19 项通过及工具版本 |
| 当前交接含义 | 可复用该教学证据；目标环境应按同一入口重新执行并保存实际结果 |
| 未运行 | 生产数据、实际员工在岗、权限、并发、通知与外部写入 |
| 判断 | 教学模型可作为设计参考；没有依据宣布生产验收通过 |

这是一份引用已有运行记录的填写样例，不伪造一次新执行。新报告应记录实际命令、环境、预期与实际差异、时间和输出位置。

## 局部交接样例 H1

**当前任务**：只复算 A/B/C/D 网络，主能力 `project-design`。输入为[定量数据](quantitative.json)，E2–E5 的设计约束沿用，不重做产品发现。

**交付**：独立资源下 CPM 工期 8 天，A–C–D 为关键路径，B 总浮动/自由浮动均为 1 天；共享团队按 B→C 顺序后为 11 天。计算前提和复算命令见[说明](quantitative.md)。

**未决与停止条件**：资源、工作日历和估算可信度未确认，所以结果不是排期承诺。当前计算与前提解释完成后结束，不展开完整应用设计。

## 跨阶段交接样例 H2

| 项目 | 内容 |
| --- | --- |
| 交接方向 | S4 应用/语义设计 → S5 契约与项目设计；再由实际工程团队实施 |
| 复用输入 | E2–E5、D1、可运行本体模型；不复制整份研究资料 |
| 假设 | H1/H2 未获真实用户或生产环境验证；U1/U2/U3 保留未知 |
| 必须保留 | 工单写权威、人员记录与实体的区分、历史区间、规则执行层、验证状态 |
| 下游要补 | 指派并发/去重、来源刷新、权限及通知失败的实现与验证活动 |
| 责任归属 | 领域负责人确认资格和状态规则，集成人员核实外部行为，测试人员保存运行证据 |
| 回退 | 时间/身份语义改变回到 S4；用户问题被推翻回到 S1；不重启无关阶段 |
| 完成 | 当前设计足以让下游识别活动和验证入口，未决项有责任角色与补证条件 |

真实任务应将责任角色落实到具体人员；没有输入授权时不虚构负责人姓名、截止时间或已完成审批。
