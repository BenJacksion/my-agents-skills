# Skill 行为评估

[首批 12 个场景](../tests/evals/cases.json)覆盖专项、边界、交接、缺失与冲突四类任务。它们用于验证能力选择、证据处理、范围控制与完成判断，不要求生成相同措辞。完整跨域输入见[工单案例](cases/maintenance/inputs.md)。

## 执行与评分

1. 固定待评估的仓库 commit，并记录工作区差异、模型、运行环境、工具可用性及日期。先用当前版本建立基线，修改后使用相同条件比较。
2. 为每个场景启动干净上下文，只给 `prompt`、`context` 所列原始材料，以及实际分发的 Skill 目录和可发现的能力描述；保留加载轨迹。被评估者的可读范围不包含 `tests/evals/`、本评分协议或历史回答；环境无法隔离时记录为非盲评，不宣称独立盲测。
3. 保存原始回答与工具轨迹。场景只要求设计时不连接真实平台；需要写操作或真实用户实验的场景另行满足对应授权和条件。
4. 由评审者对下表每项给 0/1/2 分：0=未满足或错误，1=部分满足，2=有可追溯依据地满足。每项引用回答中的证据位置并写理由。
5. 逐项检查 `criteria`，并检查是否出现 `forbidden_claims` 所代表的实质错误，不用字符串匹配代替语义判断。允许同义表达和合理替代方案。

| 维度 | 评审问题 |
| --- | --- |
| 路由与范围 | 主能力是否合理，是否只展开必要工作？ |
| 证据与未知 | 是否保留材料来源、假设与未运行状态，关键冲突是否被识别？ |
| 专业正确性 | 是否满足场景规则、数值或语义要求，并解释边界？ |
| 交付与停止 | 产物能否支持当前决策或交接，是否在完成或缺关键证据时停止？ |

首轮约定：每项至少 1 分，总分至少 7/8，所有场景专属条件满足且无禁止性实质错误才通过。选错责任能力、编造验证通过或把上游假设升级为事实直接失败；分数不能抵消。阈值是本项目的评审约定，变更时记录理由，不用于宣称统计显著性。

`acceptable_primary` 列出常见合理入口而非封闭答案集；`required_skills` 表示预期专业能力，不强迫使用特定工具或启动 Agent 进程。采用其他能力且论证充分时，由评审记录例外及理由；用户已明确点名且适用时应优先遵循。空入口列表表示可直接处理或向仓库外实现能力交接。

## 记录方式

每次运行保存到独立目录，例如 `.tmp/eval-runs/2026-10-30/`，记录：场景 ID、源码 commit/差异、模型与环境、给定输入、实际加载的 Skill、回答文件、工具轨迹、评审者、四项分数、专属条件逐项结论、证据位置、例外和最终状态。未执行场景使用“未运行”，不得填入通过分数。

首次比较逐案审查；边界场景可重复运行以观察不稳定性，并报告次数和分布，不把一次通过推广为稳定保证。修改 rubric 时保留旧版本与结果，避免看到答案后改变门槛。

## 自动检查的边界

`test_evaluation_dataset.py` 只检查场景标识、能力引用和上下文文件是否有效；CI 中该测试通过不表示 12 个行为场景通过。本次交付了场景和评审协议，尚未执行独立模型盲测，没有行为通过率基线。

专业计算的自动回归见[定量案例](cases/maintenance/quantitative.md)及[本体案例](../domains/ontology-modeling/skills/ontology-modeling/references/executable-example.md)，它们的通过也不能替代上述行为评估。
