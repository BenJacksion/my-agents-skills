# 架构概念开发

## 关键区分

先描述系统必须实现的功能，再讨论系统如何工作。无关特定方案的功能描述价值相关操作数的期望变化；概念则描述整体工作原理、操作方式或服务交付。

## 执行步骤

1. 从受益者和目标中提取与方案无关的功能；删除“使用某技术/组件”的隐含前提。
2. 以非结构化创新和结构化创新并行发散，生成多个真正不同的概念。
3. 为每个概念扩展内部功能，形成概念片段，并组合成整体概念。
4. 补充操作概念：谁操作、何时操作、操作顺序、协调对象、正常/异常情境。
5. 若交付的是服务，补充服务概念：客户如何获得价值，产品在其中扮演工具还是操作数。
6. 用能区分概念的目标筛选，保留 2-3 个深入方案；记录淘汰理由。
7. 从 Level N 递归扩展到 Level N+1：功能扩展、定义形式、映射功能、检查下一层关系、重做分组。
8. 用聚类或 DSM 辅助模块建议，但不把算法输出直接当架构。

## 概念卡片

每个候选至少写：总体工作原理、关键功能流、形式假设、价值优势、主要风险、依赖、可验证性、可演化性和不适用条件。

## 质量门槛

- 至少两个候选概念在工作原理或关键交互上真正不同；
- 需求、功能、概念和形式可追溯；
- 先发散后收敛，不把第一个可行方案当答案；
- 概念筛选使用有区分力的目标，不伪造精确分数。
