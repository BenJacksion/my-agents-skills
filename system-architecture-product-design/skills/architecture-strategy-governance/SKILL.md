# 架构策略与治理

## 架构师职责

架构师是解决歧义、发挥创造力和简化复杂度的专才，负责系统完整性、映射规范、架构基线和决策沟通，不替代所有实现团队。

## 执行步骤

1. 建立歧义台账，区分模糊、不确定、缺失、矛盾和错误信息。
2. 识别受益者、利益相关者及其直接/间接交换；记录需求来源、冲突和优先级依据。
3. 将需求转为完备、一致、有挑战性、可达成且可区分概念的目标。
4. 用系统问题陈述明确目标、边界、价值相关操作数、生命周期和硬约束。
5. 使用 ABCD 视角检查公司策略、市场/竞争、法规、技术融合、实现/供应链、操作、遗留元素、平台、产品系列和渠道。
6. 分别检查商业论证与技术架构是否“闭合”：商业上值得投资，技术上能达标且可交付。
7. 让架构基线服务于并行团队和供应商；模块和接口设置单一责任主体。
8. 为产品演化定义稳定接口、变化点、复用边界和退出条件。

## 必须交付

歧义台账、利益相关者图、需求-目标追溯、上下游影响图、ABCD 闭合检查、架构基线、责任矩阵和治理节奏。

## 质量门槛

- 关键权重和优先级可追溯；
- 不能只证明技术可行而忽略商业、法规和操作；
- 平台复用有稳定共性证据及退出条件；
- 架构信息允许迭代更新，不把早期假设伪装成定论。
