# 复杂系统架构

将架构视为一组早期、高影响、变更代价高的决策。架构工作的目标是解决歧义、聚焦创新、简化复杂度，使系统通过形式承载功能并向受益者交付价值。

## 选择工作模式

- **分析已有系统**：从形式入手，识别形式对象、关系、伴生系统、边界和使用情境；再分析功能及形式-功能映射。
- **创建新系统**：从受益者、利益相关者和需求入手，把需求转换为目标；生成多个概念，再形成架构。
- **支持架构决策**：当候选组合较多时，建立决策、选项、约束和衡量指标，探索权衡空间。

若问题只是明确架构下的局部编码或配置，直接处理局部任务，不套用完整流程。

## 共同原则

1. **涌现**：从实体功能及实体间的功能交互推断系统级功能、行为、性能和失效。
2. **整体**：同时观察上层系统、当前系统和下层实体，不把局部最优当作整体最优。
3. **聚焦**：只深入决定价值、性能、成本、风险或演化的少数关键问题。
4. **二元**：人造系统同时存在于物理领域和信息领域；软件也有形式、关系和边界。
5. **受益与价值**：识别价值相关操作数及其跨越系统边界的变化；价值是有成本的利益。
6. **解耦功能与方案**：先形成与特定解决方案无关的功能，再探索概念与形式。
7. **演化**：理解遗留元素，把稳定部分定义为接口，使元素能够演化。
8. **复杂度约束**：区分必备复杂度、实际复杂度和表面复杂度，使实际复杂度尽量接近必备复杂度。

## 分析已有系统

1. 确定系统及其形式与功能。
2. 确定实体、实体的形式与功能、系统边界和外围环境。
3. 确定实体关系及边界处关系的形式与功能。
4. 根据实体功能和功能交互推断涌现属性与失效。
5. 分析形式：对象、结构、伴生系统、接口和使用情境。
6. 分析功能：用“过程 + 操作数”描述功能，找出主要/次要外部功能、内部功能、功能交互和价值通路。
7. 建立形式-功能映射，指出支持层、非理想因素、操作者、行为和操作成本。
8. 根据受众选择架构投射；保留模型中的完整信息，不让简图抹去关键关系。

## 创建新架构

1. **解决上游歧义**：明确公司策略、市场、法规、技术成熟度、供应链、实现、操作、遗留元素、平台与产品系列。
2. **确定需求来源**：识别受益者和利益相关者，分析交换关系与间接价值，给需求分组和排序。
3. **把需求转换为目标**：写出可解决的系统问题陈述；目标应完备、一致、具挑战性且可达成，并能区分候选概念。
4. **确定无关方案的功能**：描述价值相关操作数的期望变化，不嵌入预选形式。
5. **生成概念**：结合非结构化创新与结构化创新；先发散概念，再扩展内部功能和概念片段，组合为多个整体概念。
6. **筛选概念**：保留 2-3 个值得展开的概念；使用有区分力的目标及优雅程度评估，不用伪精确评分掩盖判断。
7. **从概念到架构**：逐级扩展功能架构、定义形式并映射功能。为判断 Level N 的分组，至少查看 Level N+1 的关系。
8. **选择分解**：比较功能、时间、供应商、操作、制造、组织等分解平面；优先组内交互强、组间交互弱的方案。
9. **定义接口与交付物**：记录系统边界、形式结构、功能架构、形式-功能映射、关键接口、涌现目标和决策依据。

## 支持架构决策

1. 将架构问题表示为决策、选项、约束和衡量指标；架构决策通常是类别变量且彼此强耦合。
2. 选用合适模式：`DECISION-OPTION`、`DOWN-SELECTING`、`ASSIGNING`、`PARTITIONING`、`PERMUTING` 或 `CONNECTING`。
3. 枚举可行时使用全因子排列；组合爆炸时使用透明、可解释的启发式搜索，并纳入领域知识。
4. 检视模糊帕累托前沿和权衡空间结构，识别好架构、主导决策及分群。
5. 做敏感度分析，优先考虑能应对环境变化的健壮架构。
6. 按决策对指标的敏感度及决策间耦合度排序：高敏感、高耦合的决策优先并成组处理。
7. 决策工具只提供展示、结构、模拟和观察支持；保留专家解释与判断的可追溯性，不让模型替代架构师。

## 输出

按任务规模选择必要产物，不机械输出全部章节：

- 系统问题陈述、边界、环境和关键假设；
- 受益者/利益相关者、需求优先级、目标和价值通路；
- 无关特定方案的功能、候选概念及筛选理由；
- 形式、功能、映射、分解、接口和预期涌现；
- 架构决策、选项、约束、衡量指标、权衡和敏感度；
- 风险、验证方式、演化影响和未决问题。

将事实、假设、推断和决策分开标记。权重和优先级必须来自用户或可追溯依据；缺少会改变方案方向的信息时，列出歧义并集中提问。

## 完成检查

- 系统边界、外围环境、伴生系统和使用情境是否明确？
- 价值是否通过跨边界功能与操作数变化说明？
- 功能是否与特定解决方案解耦？
- 是否生成并比较了真正不同的概念？
- 分解是否检查了下一层关系和多个分解平面？
- 关键接口、涌现行为和失效传播是否明确？
- 高影响决策是否有依据、敏感度和复审条件？
- 实际复杂度是否被压向必备复杂度，而非只隐藏表面复杂度？
