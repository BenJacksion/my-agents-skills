# 云端交付与自动化运维

把云和容器当作承载业务运行与交付约束的机制，必须和应用运行模型、数据状态及团队运维能力一起设计。

## 执行协议

1. 明确环境、部署单元、发布频率、回滚目标、可用性、容量、合规和成本约束。
2. 识别无状态/有状态组件、配置与密钥、数据持久化、网络入口、依赖服务和故障域。
3. 比较虚拟机、容器、编排平台、服务网格、托管服务和混合部署等候选；不把 Kubernetes 等同于云原生。
4. 设计构建、测试、发布、迁移、回滚、扩缩容、备份、恢复和观测链路。
5. 检查平台抽象是否隐藏了真实资源、网络、权限、数据和运维责任。
6. 输出最小可运行基线和逐步自动化路径，不把工具清单当成交付方案。

## 判断原则

- DevOps 是开发、测试、发布和运维责任的闭环，不等于安装流水线工具。
- 容器化不自动解决有状态服务、数据迁移、网络故障和可观测性。
- Kubernetes 只有在编排复杂度、环境数量、弹性或团队能力支持时才是候选。
- 云原生还应检查可观测性、弹性和声明式交付，而不只检查容器和编排。
- 云架构必须同时说明资源成本、供应商耦合、恢复目标和责任边界。

## 最小交付

- 运行/部署拓扑；
- 交付流水线与环境策略；
- 状态、数据、配置、权限和秘密管理；
- 观测、扩缩容、故障恢复和回滚方案；
- 成本、供应商耦合、运维责任和验证行动。
