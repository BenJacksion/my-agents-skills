# 模型演进与行动验证

修改已被数据、查询或业务行动使用的模型时读取。以下是以工单为例的设计契约，不代表 Foundry 已提供对应的并发、重试或迁移机制。

## 从单负责人演进到多角色指派

变化的业务要求：保留主负责人历史，并允许审核人员参与。旧版 `Ticket → legacyOwner → Employee` 无法保存角色和有效区间；新版使用 `Assignment(ticket, assignee, role, validFrom, validTo)`。

| 影响面 | 最小处理 | 验证 |
| --- | --- | --- |
| 身份 | 工单与人员标识保留；给指派记录分配稳定标识 | 重跑转换不生成重复指派，既有标识不被占用 |
| 数据 | 可信的旧负责人及生效时间转为 Primary 指派；保留快照来源与记录时间 | 无生效时间或旧负责人不唯一时拒绝自动转换，不以迁移时间伪造历史 |
| 查询 | 通过角色和有效时间查主负责人；未绑定答案显式报告未知 | 正常、无记录、换人边界、多角色和重叠区间均有用例 |
| 约束 | 每条指派恰好一个人员；同一工单 Primary 区间不重叠 | 多人协作通过，多个重叠主负责人失败；无指派可按范围允许 |
| 行动 | 改为结束旧指派并创建新指派，不只覆盖一个属性 | 两步业务修改的一致性与并发冲突在目标环境验证 |
| 旧消费者 | 如仍需单负责人，提供指定时间的 Primary 投影并设置弃用条件 | 投影不携带角色和历史，不能宣称新旧模型双向无损 |

[可运行案例](executable-example.md)包含受控 v1 快照到 v2 的转换和答案回归。它没有实现线上迁移、任意旧数据清洗或平台配置更新。

生产演进按实际风险裁剪：确定模型与数据版本 → 保存可恢复快照和消费者清单 → 对新旧结果做影子比对 → 明确切换期间唯一写入权威 → 切换并观察 → 按约定弃用旧接口。任何步骤失败时保留证据并停止切换；恢复旧读接口前核查新增角色和历史是否会丢失，不能只回滚 schema。

## 业务状态与转换

示例将持久工单状态保存为 Open/Closed；“未指派/已指派”由查询时有效的 Primary 指派派生，避免维护两份相互矛盾的当前负责人状态。

| 原状态 | 意图 | 条件 | 预期结果 |
| --- | --- | --- | --- |
| Open，未指派 | 指派 | 有调度权限；人员有效且符合在岗要求 | 新建有效指派，读取结果为新负责人 |
| Open，已指派 | 重新指派 | 有权限；校验读取版本仍有效；新人员合格 | 旧区间结束、新区间开始，不产生重叠 Primary |
| Open | 关闭 | 有关闭权限且满足业务完结条件 | 变为 Closed；按约定结束有效指派，历史保留 |
| Closed | 指派或重新指派 | 本例禁止 | 执行端拒绝，对象与外部状态不变 |

“在岗要求”和“读取版本校验”是本例业务设计，未在 RDF 数据案例中实现。重开工单、撤销和追溯更正仅在真实需求出现时补充，不默认开放。

## 将要求、平台证据与待验证项分开

| 情况 | 业务要求 | 平台证据或限制 | 待环境验证与责任 |
| --- | --- | --- | --- |
| 同时重新指派 | 不出现两个重叠 Primary；失败方收到可处理的冲突 | 不从 Action“单次事务”推导跨请求串行化 | 核实版本条件或其他冲突控制；应用/平台负责人定义冲突提示与重试条件 |
| 重复提交 | 同一业务请求不重复创建指派或发送外部指令 | 不假设默认恰好一次或存在幂等开关 | 核实请求标识与去重存储；无法保障时先阻止自动重试并交人工核对 |
| 来源刷新 | 保留已批准编辑并维持事实权威一致 | 刷新与编辑协调依赖实际配置 | 数据负责人验证刷新前后读值、删除与冲突策略 |
| 通知失败 | 对象成功与通知失败分别可见 | 研究时官方文档说明通知失败时对象编辑仍可能成功 | 通知负责人核实送达与重试，避免重试整个指派行动 |
| 外部写入超时 | 区分未发出、已失败和结果未知 | 不把对象编辑事务推广为跨系统 ACID | 集成负责人用请求标识查询外部结果；无法确认则保持待核对，停止盲目重试 |
| 越权或非法状态 | 执行端拒绝；不写入、不触发副作用 | submission criteria 不等于完整写权限 | 权限负责人分别验证读取、执行、写入传播及审计可见性 |

每项保留执行者、输入版本、请求标识（若实现支持）、前后状态、对象提交结果和外部确认。推理生成的事实和审计记录也可能泄露信息，应对实际消费者检查可见范围；不把“能够推导”视为“允许公开”。

平台事实继续采用[运营模式](operational-ontology.md)中注明日期的来源。无真实环境时，本节状态转换、权限、并发、幂等和副作用测试均标记为未运行；本地 RDF/OWL 验证不能替代它们。
