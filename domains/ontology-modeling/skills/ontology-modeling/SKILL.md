# 本体建模

让模型能够回答约定的问题或支撑业务行动。执行所需规则和参考均保存在本 Skill 目录内，可单独使用。

## 确定任务与范围

- 新建：从问题、领域材料和代表性数据建立最小模型。
- 评审：保留已有模型，先用问题和反例定位缺口，输出证据、影响与最小修正；只在用户要求时修改模型。
- 演进：明确变更前后的语义、受影响实例/查询/行动和迁移方式，再运行相关回归用例。

已有范围、术语或数据映射可直接复用。缺少信息时标记假设；只有缺失信息会改变模式、身份或关键业务规则时集中澄清。概念设计可先交付模型与验证计划，无需等待平台环境。

## 选择模式

- 共享语义、逻辑分类、跨源知识集成、RDF/OWL：读取[知识工程模式](references/knowledge-engineering.md)。
- Foundry 或对象驱动的业务操作闭环：读取[运营模式](references/operational-ontology.md)。非 Foundry 实现只借鉴方法，不声称拥有其平台机制。
- 两者均需：读取两份参考，先共用词汇，再分别实现；显式记录映射损失。只有“本体”一词而目标不明时，先澄清目标，不默认联合模式。

## 共用执行协议

1. 定义范围和代表性的待回答问题（能力问题）；运营模式增加决策、执行者与业务行动。每项给出预期答案或状态变化。
2. 从领域证据识别概念/对象类型、实例、角色、事件、属性与关系。定义术语、反例与上下文；同名不等于同义，角色或暂时状态不自动成为永久子类。
3. 明确身份：业务标识、跨源同一性、命名空间、合并/拆分与历史。属性说明类型、单位、时间、缺失含义和来源；关系说明方向、两端类型与适用范围。
4. 关系带时间、角色、数量或来源时，评估独立关联实体；不要把有业务含义的关系元数据丢进模糊字符串。
5. 将每条规则标为推理公理、数据校验、行动前置条件、授权或外部流程。未知不等于假；推理成立不等于数据合规，更不等于获准执行。
6. 映射模型到真实数据，记录转换、来源、所有者、更新时间、冲突规则及权威系统。复用已有词汇前检查定义、许可、版本和兼容性，而非凭名称匹配。
7. 按所选模式构建最小纵向样例，以正常、异常和边界用例验证。只有任务需要时才生成代码、OWL 或平台配置；运行结果与验证计划分开报告。
8. 根据失败收敛模型，记录语义/身份变更、实例迁移、兼容性和维护责任。新增元素不能支持任何问题或行动时，优先删减。

## 联合模式的额外检查

- 分别映射 OWL 类/实例到对象类型/对象、数据属性到对象属性、对象属性到链接；映射是设计决策，不是自动等价。
- OWL 子类、等价类、属性链和开放世界推理不默认有 Foundry 对应机制；接口多态不直接等同于 OWL 继承语义。
- OWL 公理不能替代行动准入；SHACL 约束也不会自动成为 Foundry submission criteria。
- 行动作为知识工程中的实体或事件描述，不会因此获得执行能力。状态、历史、权限与副作用在运营侧独立实现。

## 最小交付

按任务规模合并为一份模型说明，已有材料用引用复用，不为每项另建文件：

| 内容 | 最少记录 |
| --- | --- |
| 范围与问题 | 模式、问题/行动、预期答案或状态变化、排除项 |
| 模型与映射 | 定义、身份、属性、关系、规则执行层、数据来源与更新责任 |
| 验证追溯 | 问题/规则 → 模型元素 → 样例 → 预期 → 实际结果或未运行原因 |
| 决策与交接 | 事实、假设、证据、取舍、未决问题；变更任务补充兼容性与迁移影响 |

仅对所选能力执行检查：用到 OWL 才检查推理，用到 SHACL 才校验 shapes，用到行动才验证授权与状态变化。评审输出按影响排序的发现；无问题时说明已覆盖范围和未验证项。
