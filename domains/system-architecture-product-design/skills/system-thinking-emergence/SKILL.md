# 系统思维与涌现

## 核心定义

系统是由一组实体及实体之间的关系构成、整体功能大于各实体功能之和的集合。架构分析的对象不是孤立组件，而是实体、关系、边界、环境和由交互产生的涌现。

## 执行步骤

1. 写出当前系统问题、观察者和分析层级；同一实体在不同层级可能既是系统又是更大系统的部件。
2. 列出实体的形式与功能；不要把名称、部门或技术名词直接当成功能。
3. 识别静态关系、动态交互和跨边界接口，标注传递的是物质、能量、信息、命令或控制。
4. 画出系统边界、外围环境、伴生系统和使用情境；说明边界改变会转移什么责任和成本。
5. 根据实体功能和功能交互推断整体功能、性能、行为和失效；记录可验证证据或判断置信度。
6. 用自顶向下、自底向上、由外而内、由内而外四种方向交叉检查。
7. 对复杂系统做层级、类/实例、特化/泛化和递归分析；使用 SysML、OPM 或等价视图。

## 必须交付

- 系统定义与分析层级；
- 实体—关系—边界—环境表；
- 关键涌现及其形成机制；
- 失效、反馈和传播路径；
- 需要试验、模型或专家判断的未知项。

## 质量门槛

- 每个整体结论都能指向实体功能和关系交互；
- 明确哪些行为是涌现而非单个组件属性；
- 不把“每个部件都正常”当作系统验证；
- 视图简化不删除关键语义。
