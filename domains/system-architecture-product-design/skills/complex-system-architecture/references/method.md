# 方法参考

仅在需要统一术语、选择分析工具或表述优化问题时读取。

## 核心术语

| 术语 | 工作定义 | 检查点 |
| --- | --- | --- |
| 系统 | 由一组实体及其关系构成，整体功能大于各实体功能之和 | 是否明确实体、关系和涌现 |
| 形式 | 系统的物理或信息体现，对功能起工具作用 | 是否包含对象、结构、伴生系统、接口和使用情境 |
| 功能 | 产生或促进性能的动作、活动、操作或转换 | 是否写成“过程 + 操作数” |
| 操作数 | 状态被过程改变的对象 | 哪个操作数的变化体现利益 |
| 架构 | 形式与功能之间的映射，以及承载功能交互的形式结构 | 是否说明映射与接口，而非只列组件 |
| 概念 | 与特定解决方案有关、描述系统如何工作的观念 | 是否与无关特定方案的功能区分 |
| 操作概念 | 系统在交付价值时由谁、何时、如何操作及与谁协调 | 是否覆盖实际操作序列和异常情境 |
| 价值 | 有成本的利益 | 利益和成本是否对应到功能与形式 |
| 必备复杂度 | 由系统必须完成的功能驱动的复杂度 | 能否通过减少功能而降低 |
| 表面复杂度 | 系统在人看来难以理解的程度 | 是否可通过抽象、层级、分解和视图降低 |

## 系统思维四项任务

1. 确定系统及其形式与功能。
2. 确定实体、实体的形式与功能、系统边界和环境。
3. 确定实体间及边界处关系的形式与功能。
4. 根据实体功能和功能交互推断涌现属性。

涌现可借助先例、试验、模型和人的判断预测。对无先例、难试验、难建模的系统，明确判断依据与置信度。

## 思考复杂系统

- 在自顶向下、自底向上、由外而内和由内而外之间切换。
- 在形式领域和功能领域之间交替思考。
- 区分类/实例、特化/泛化和递归关系。
- 将某一级功能视为下一级目标。
- 使用“2 下 1 上”：先向下看两级，再回到上一级确定分组。
- 使用 SysML、OPM 或等价视图展示系统；符号选择服从沟通目的。

## 架构决策模式

| 模式 | 要回答的问题 | 常见例子 |
| --- | --- | --- |
| `DECISION-OPTION` | 每个决策选哪个选项 | 选择任务模式或总体概念 |
| `DOWN-SELECTING` | 从候选集合保留哪些元素 | 选择功能、设备或方案集 |
| `ASSIGNING` | 把一类实体分配给另一类实体 | 把功能分配给形式 |
| `PARTITIONING` | 如何把实体划分为若干组 | 模块、团队或卫星载荷分组 |
| `PERMUTING` | 如何安排实体顺序 | 工序、访问或集成次序 |
| `CONNECTING` | 哪些实体之间建立连接 | 网络拓扑或接口选择 |

一个问题可能同时符合多个模式。选择最贴近架构师心智模型、最便于解释结果的表达。

## 决策支持四层

1. **展示层**：向人呈现候选、指标、关系和结果。
2. **结构层**：表示决策、选项、约束及其耦合。
3. **模拟层**：计算候选架构的指标和行为。
4. **观察层**：分析权衡空间、帕累托前沿、分群和敏感度。

架构分析强调用较低保真度探索较宽的空间；详细设计强调用较高保真度分析较少方案。不要用详细模型过早缩窄架构空间。

## 复杂度与分解检查

依次检查：

1. 系统是否实现了不产生价值的功能；
2. 实际复杂度是否显著超过必备复杂度；
3. 视图是否隐藏了实际复杂度，只降低了表面复杂度；
4. 模块内交互是否强于模块间交互；
5. 分解是否同时匹配功能、制造、供应商、操作、投资和组织等重要平面；
6. 是否存在循环依赖、共享状态、单点故障或长传播链；
7. 关键接口是否有单一责任主体及验证方式。

## 方法边界

- 形态矩阵、DSM 和决策树能辅助展示与组织知识，但不足以自动解决架构问题。
- 帕累托非劣不能直接替决策者选出唯一方案。
- 启发式优化应监测算法表现，并结合领域知识；搜索结果必须可解释。
- 模型无法消除主观性与歧义。记录专家、依据、假设和判断时间，保证可追溯。
